# 03. 데이터 전략 및 검증 계획

운영측이 제공하는 것은 **소수의 예시 이미지, 샘플 코드, 관련 파일**뿐이다(p.4). 학습 데이터는 전량 참가팀이 구성해야 한다.
따라서 **데이터 구성과 검증 설계가 이 미션의 실질적 승부처**이며, 모델 선택보다 앞선다.

전제: 로컬/연구실 GPU 보유. 자체 생성 규모에 제약이 적다.

---

## 2. 생성(Fake) 이미지 — 공고문 4유형을 그대로 재현

핵심 원칙: **운영측이 명시한 유형을 그대로 재현하되, 유형마다 복수의 기법을 쓴다.** 단일 기법으로 만든 데이터는 그 기법의 아티팩트만 가르친다.

### 유형 ① 실험실 작물 + 현장 배경

```
PlantVillage 등 실험실 작물 이미지
  → SAM으로 작물 분할
  → 현장 배경(AI Hub real)에 합성
     · 단순 알파 블렌딩
     · Poisson 블렌딩 (경계 그라디언트 정합)
     · 이미지 하모나이제이션 (색/조명 정합)
     · SD 인페인팅 기반 경계 융합
  → 스케일·회전·배치 위치 무작위화
```

경계 처리 난이도를 **여러 단계로** 만든다. 전부 조악한 알파 블렌딩이면 모델이 "경계 선명도"만 배운다.

> **픽셀 공간 합성(G4)과 잠재 공간 재생성(G5)의 비율을 의도적으로 관리한다.** 위 4가지 중 앞의 3개는 픽셀 공간이라 영역 간 불일치가 남고, SD 인페인팅만 잠재 공간이라 이미지 전체가 재디코딩된다. **탐지 원리가 정반대이므로**(`06` §8) 한쪽에 치우치면 그 반쪽만 배운다. §4.3의 유형별 성능 리포트도 ①②를 G4/G5로 한 단계 더 쪼개서 본다.

### 유형 ② 현장 작물 + 다른 현장 배경

유형 ①과 동일한 기법, 소스만 **현장 촬영 작물**로 바꾼다.
→ 작물 픽셀도 배경 픽셀도 모두 진짜인, **가장 어려운 유형**. 여기서의 성능이 B3 브랜치의 존재 이유다.

### 유형 ③ 스타일 변환

- SD img2img (strength 0.2 ~ 0.6 구간을 넓게 샘플링 — 약한 변환일수록 어렵다)
- ControlNet 기반 조건부 변환
- InstructPix2Pix 계열 지시 기반 편집
- CycleGAN 등 GAN 기반 도메인 변환
- 고전적 뉴럴 스타일 트랜스퍼

### 유형 ④ 전체 생성

- SD 1.5 / SDXL / SD3 / FLUX / Kandinsky 등 **계열을 나눠서**
- 작물 도메인 LoRA 파인튜닝 버전 포함 (일반 SD의 "토마토 온실"은 실제 시설과 다르게 생겼다 — 도메인 적합도가 낮은 가짜만 학습하면 실전에서 무너진다)
- sampler / step 수 / CFG scale / 해상도를 넓게 변화
- **dev(full-step)와 schnell/Turbo(소수 스텝)를 반드시 섞는다.** 소수 스텝 증류 모델만 쓰면 "스텝이 적을 때의 흔적"을 배우게 되고, 운영측이 full-step을 썼다면 그대로 어긋난다(`06` §7)
- **오토리그레시브 계열 추가 검토** — GPT Image 등 상용 도구가 이 계열로 이동했다. **노이즈에서 출발하지 않아 저수준 단서 논리가 원리적으로 통하지 않는 계열**이므로, 소량이라도 확보하면 취약점을 미리 진단할 수 있다(`06` §4)

### 2.1 짝(pair) 생성 원칙

가능한 한 **동일한 real 원본에서 fake를 파생**시킨다.
- 이유: real은 토마토, fake는 딸기 식으로 콘텐츠가 갈리면 모델은 "진위"가 아니라 "작물 종류"를 학습한다.
- 유형 ①②③은 원본 파생이 자연스럽다. 유형 ④는 원본의 프롬프트/구도를 참조해 콘텐츠 분포를 맞춘다.

### 2.2 생성기 수는 무작정 늘리지 않는다

"이점 후 충돌(Benefit then Conflict)" — 이질적 생성기를 무한정 섞으면 특성 공간에서 real/fake 분포가 겹치며 성능이 정체·하락한다.

**운영 규칙**
1. 생성기를 **계열별로 그룹화**한다. `06` 조사 결과에 따라 **5그룹**으로 나눈다.

   | 그룹 | 내용 |
   |---|---|
   | G1 확산-잠재 | SD1.5, SD2.1, SDXL |
   | G2 플로우 매칭 | SD3/3.5, FLUX.1-dev |
   | G3 GAN | CycleGAN, StyleGAN 계열 |
   | G4 편집-픽셀공간 | 알파 / Poisson / 하모나이제이션 |
   | G5 편집-잠재공간 | SD 인페인팅, img2img |
   | (G6 오토리그레시브) | 자원이 허락하면 추가 — 상용 도구가 이 계열로 이동 |

   ※ **SD3·FLUX를 SD1.5·SDXL과 같은 그룹에 두면 안 된다.** 전자는 rectified flow, 후자는 확산이며 궤적·스케줄이 다르다. 한 그룹으로 묶으면 계열 이동을 재려는 LOGO CV가 계열 이동을 재지 못한다(`06` §6).
   ※ 증류·소수스텝(Turbo/schnell/LCM)은 별도 그룹이 아니라 **G1·G2 안에서 스텝 수를 흔드는 축**으로 둔다. 단 ADD 계열은 판별자를 쓰므로 GAN 흔적이 섞인다(`06` §7).
2. 계열을 추가할 때마다 **LOGO CV로 실제 이득을 측정**하고, 이득이 없으면 되돌린다.
3. 필요 시 계열별로 분리 학습 후 융합한다(브랜치 분리와 동일한 논리).

## 3. 후처리 증강 규격 — real·fake 양쪽에 **동일하게** 적용

압축 shortcut을 차단하는 것이 목적이다. 한쪽에만 적용하면 편향을 만드는 것이므로 반드시 대칭으로 적용한다.

| 증강 | 파라미터 |
|---|---|
| JPEG 압축 | QF ~ U(30, 100), 다중(2회) 압축 포함 |
| 리사이즈 | 배율 U(0.5, 1.5), 보간 {bicubic, bilinear, lanczos, nearest} 무작위 |
| 가우시안 블러 | σ ~ U(0.1, 3.0) |
| 가우시안 노이즈 | 낮은 강도 |
| 컬러 지터 | 밝기·대비·채도·색조 |
| 저장 포맷 | PNG / JPEG 무작위 혼합 |
| 적용 순서 | 무작위 셔플 (압축→리사이즈 vs 리사이즈→압축의 흔적이 다르다) |

**학습 시 crop 원칙**: 리사이즈로 입력 크기를 맞추지 않는다. 학습은 RandomCrop, 추론은 CenterCrop + 멀티크롭 평균.
(단 FerretNet은 256² 입력을 전제하므로, **리사이즈가 아닌 crop으로 256²를 만드는지** 구현을 확인하고 필요하면 수정한다.)

## 4. 검증 프로토콜 — 계획서의 차별화 포인트

리더보드 제출 횟수가 제한될 가능성이 높으므로(설명회 안내 예정), **로컬 검증의 신뢰도가 곧 경쟁력**이다.

### 4.1 LOGO — Leave-One-Generator-Out CV (최우선)

학습에 쓰지 않은 생성기로 평가한다. **"운영측의 미지 생성기"에 대한 대응력을 사전에 추정하는 유일한 방법**이다.

```
생성기 계열을 K개 그룹으로 분할
for k in 1..K:
    학습: 그룹 k를 제외한 전부
    평가: 그룹 k
→ 평균과 최악 케이스를 함께 본다. 최악 케이스가 실전 하한선이다.
```

### 4.2 Leave-one-farm / camera-out

Real 쪽 도메인 이동 내성을 측정한다. 특정 농가·카메라를 학습에서 제외하고 평가한다.
→ "이 카메라 = 진짜"를 학습했는지 진단하는 장치.

### 4.3 유형별 개별 성능 리포트

①~④ 각각의 정확도·재현율을 **항상 분리해서** 본다. 전체 평균만 보면 유형 ②의 실패가 가려진다.

| 유형 | 기대 담당 브랜치 | 경고 신호 |
|---|---|---|
| ① 실험실+현장 합성 | B3 | B3 없이 전체 점수가 높다면 shortcut을 의심 |
| ② 현장+다른 현장 합성 | B3 | 여기가 낮으면 B3 설계를 재검토 |
| ③ 스타일 변환 | B1, B4 | 약한 strength 구간에서 급락하는지 확인 |
| ④ 전체 생성 | B0, B1, B2 | 가장 쉬운 유형. 여기서 낮으면 기본 파이프라인 문제 |

### 4.4 강건성 스윕

JPEG QF, 리사이즈 배율, 블러 σ를 축으로 성능 곡선을 그린다. 특정 압축 구간에서 절벽이 있으면 그 구간의 증강을 보강한다.

### 4.5 예시 이미지 취급

운영측 제공 예시 이미지는 **검증 전용**으로만 쓴다. 수가 적어 학습에 넣으면 과적합되고, 검증 기준을 잃으면 로컬 신뢰도가 무너진다.
