## 1. 이미지 미션 요구사항 (p.4, p.7)

- 대상 작물 이미지가 **실제 현장 이미지인지 생성 이미지인지 판별하는 이진 분류 모델**
- 실제 현장 이미지 = 농가 또는 시설에서 **직접 촬영된** 작물 이미지
- 생성 이미지에 포함될 수 있는 유형 4가지:
  1. **실험실 작물 + 현장 배경** 결합 이미지
  2. **현장 작물 + 다른 현장 배경** 결합 이미지
  3. 실제 이미지의 **스타일 변환** 이미지
  4. **전체 생성** 이미지
- 제출물: Google Colab에서 **실행 가능한 추론 코드 + 학습 완료 모델 + 관련 설정파일**
- 평가: 참가팀에 **공개하지 않은** 테스트 이미지를 운영 플랫폼 평가환경에서 자동 추론
- 제약: **일반적인 Google Colab 자원 범위**에서 정상 실행되어야 함

> 세부 평가지표·점수 환산·제출 횟수·기술적 제출 규격은 **개막설명회(9/18)에서 안내**된다. 미확정 사항은 `03` 문서 말미의 질문 리스트로 관리한다.

## 5. 메타데이터 취급 원칙

파일 메타데이터(EXIF/XMP, JPEG 양자화 테이블, PNG chunk, ICC 프로파일)는 **개발 단계의 정찰 정보로만** 쓰고 **추론 로직이 의존하게 만들지 않는다.**

- 근거 1: 운영측이 테스트 이미지를 균일하게 재인코딩하면 단서가 사라져 성능이 붕괴한다.
- 근거 2: 반대로 실제/생성 이미지가 서로 다른 저장 파이프라인을 거쳤다면 그것은 **데이터셋 편향(shortcut)** 이며, 이에 의존한 모델은 일반화 실패로 최종 검증(p.8)에서 문제가 될 수 있다.
- 활용 방식: 예시 이미지의 메타데이터를 **로컬 분석**해 생성기 계열과 재인코딩 여부를 추정하고, 그 결과로 *학습 데이터 구성과 브랜치 가중치*를 조정한다. 추론 입력으로는 픽셀만 사용한다.

## 6. 재현성 요구사항 (p.8, p.10)

최종 검증은 **재현 가능성과 규정 준수 여부**를 본다. 재현되지 않으면 성적이 무효 처리될 수 있다.

- 시드 고정: `torch.manual_seed`, `numpy.random.seed`, `random.seed`, `torch.use_deterministic_algorithms(True)`
- `cudnn.benchmark = False`, `cudnn.deterministic = True`
- 추론에 무작위성이 필요하면(TTA 등) 시드를 고정하고 결과의 결정성을 검증
- 보관 항목: 실제 활용한 **학습데이터 목록**, 전처리·학습·추론 코드, 모델 및 설정파일, 실행환경(버전 고정된 requirements), 실행방법
- 제출기한 이후 수정은 **동일 예측결과 재현을 위한 실행환경·경로·설정 수정에 한정**된다(p.10). 모델 구조·가중치·예측결과를 바꾸는 보완은 허용되지 않으므로, **기한 내에 완결된 상태로 제출**해야 한다.

### 7.2 반드시 지켜야 할 세 가지

**① 추론이 배치에 의존하면 안 된다 — 가장 중요**

p.8은 *"제출 결과가 정상적으로 재현되지 않거나 … 규정 위반이 확인되는 경우 성적을 무효 처리할 수 있음"*, p.10은 *"제출한 코드와 모델만으로 결과가 재현 가능하여야 함"* 을 요구한다.

> **테스트 배치 전체의 스코어 분포로 정규화하거나, BatchNorm 통계를 테스트 데이터로 갱신하면 같은 이미지라도 어느 배치에 들어가느냐에 따라 예측이 달라진다.** 이는 재현 불가이며 성적 무효 사유가 될 수 있다.

우리 설계는 이미 *"각 지표는 **검증셋 기준으로** 정규화"*(`02` §4.6)라 안전하다. **이를 설계 원칙으로 못박는다.**

- 지표 정규화 파라미터(평균·표준편차 또는 분위수), 가중치 wᵢ·vⱼ, 임계값 τ → **전부 학습·검증 단계에서 고정해 설정파일로 제출.** 추론 시 테스트 데이터의 통계를 일절 쓰지 않는다
- 축 B의 정상 분포 모델도 동일 — 학습 시점에 고정한다
- BatchNorm은 추론 시 **eval 모드 고정** (running stats 갱신 금지)
- **TTA 크롭 위치는 고정 격자**로 한다. 무작위 크롭은 시드를 고정해도 이미지 처리 순서에 따라 결과가 달라질 수 있다
- **검증 방법**: 같은 이미지를 `batch=1`과 `batch=16`으로 각각 추론해 **예측이 완전히 일치하는지** 확인한다. 제출 전 필수 절차로 둔다

**② 문서화 의무가 실제 작업량이다**

p.5는 외부·자체 생성 데이터의 **출처·이용조건·생성방법·활용방법** 명시를 의무화한다. 우리는 계열별로 생성기를 여러 개 쓰므로 대상이 많다.

→ **지금부터 생성 로그를 남긴다.** 나중에 몰아서 쓰면 재현이 안 된다.

| 기록 항목 | 예 |
|---|---|
| 생성기 이름·버전·라이선스 | `FLUX.1-schnell v1.0, Apache-2.0` |
| 생성 파라미터 | 스텝 · CFG scale · 해상도 · 샘플러 |
| 시드 | 재현용 |
| 원본 이미지 출처 | 유형 ①②③은 파생 원본이 있다 |
| 산출 장수 | 계열별 |

**③ 자체 촬영분의 초상권·이용 동의**

p.5: *"저작권, 초상권, 개인정보, 이용 조건을 침해하는 데이터는 사용할 수 없음"*

- 작업자가 찍힌 프레임은 **배제하거나 마스킹**한다
- **농가 촬영 동의를 서면으로 받아 둔다.** 시설 내부 구조가 영업 정보일 수 있고, p.5상 최종 제출 시 학습데이터 제출 의무가 있어 촬영분이 주최측에 전달된다

### 7.3 예시 이미지 — 규정과 방법론을 구분한다

`03` §4.5는 운영측 제공 예시 이미지를 **검증 전용**으로 쓰기로 정했다. **이건 규정 때문이 아니라 방법론적 선택이다.**

- **규정상**: 학습에 써도 된다. p.9는 "대회 수행 목적으로만 이용"을 요구할 뿐이고 학습은 대회 수행에 해당한다
- **방법론상**: 수가 적어 과적합되고, 검증 기준을 잃으면 로컬 검증의 신뢰도가 무너진다

→ **9/18에 예시 이미지 수가 예상보다 많으면 이 판단을 재검토할 수 있다.** 규정이 막는 것이 아니기 때문이다.
