# 07. 설계안 비교 — 원안 검토와 대안 A~D

작성일: 2026-09-07 · 근거: 논문 조사(§2), 공고문 규정(`01`), 계열 조사(`06`)

---

## 0. 원안

```
이미지 → 작물만 누끼
      → ① 생성 AI 계열 구분 모델 (디퓨전 / DiT / GAN / VAE)
      + ② 작물의 농업적 특성 오류 확인 모델
      → 가중치 부여해 통합 → AI 여부 판정
```

**두 브랜치를 나눈 발상(생성 흔적 축 + 도메인 지식 축)은 문헌과 정확히 맞고, 본 대회에서 특히 강하다.** §2에서 각각의 대응 연구 분야를 확인했다. 다만 세 군데를 손봐야 한다 — 계열 분류 라벨(§1), 누끼의 위치(§3.1), 계열 분류의 사용 방식(§3.2).

## 1. 계열 4분류 라벨 정정

| 원안 | 실제 | 정정 |
|---|---|---|
| 디퓨전 | 확산 모델. 백본이 U-Net (SD1.5, SDXL) | **확산-U-Net** 으로 명명 |
| **DiT** | **디퓨전의 백본 이름**이지 별개 계열이 아니다. U-Net 자리를 트랜스포머로 바꾼 것 | **"트랜스포머 백본은 다르다"는 직관은 맞다.** 실제로 이 계열(SD3·FLUX)은 MMDiT + **플로우 매칭**이라 궤적·스케줄이 다르다 → **플로우 매칭(DiT)** 으로 명명 |
| GAN | 맞다. 단 2026년 텍스트→이미지에서는 거의 퇴장 | 유지. 단 **스타일 변환(CycleGAN)과 증류의 판별자**로 살아 있음 |
| **VAE** | **VAE로 이미지를 만드는 생성기는 실무에 없다.** VAE는 SD·FLUX 안에 들어 있는 압축기(잠재↔픽셀) | **오토리그레시브(토큰 예측)** 로 교체. GPT Image 등 상용 도구가 이 계열이고, **노이즈에서 출발하지 않아 저수준 단서가 원리적으로 무효**라 반드시 따로 봐야 한다 |

**정정된 4계열**: 확산-U-Net / 플로우 매칭(DiT) / GAN / 오토리그레시브

> VAE를 계열에서 빼는 대신, **VAE 디코더 자체는 최고의 단서로 남는다.** 확산·플로우매칭·증류·잠재 인페인팅이 전부 마지막에 이 디코더를 통과하므로, 그 재구성 오차 하나가 네 계열을 동시에 겨냥한다(`06` §3).

## 2. 논문 조사 — 원안의 각 부분에 대응하는 연구가 있는가

### 2.1 ① 계열 구분 모델 → **Model Attribution.** 있다. 그러나 치명적 약점이 있다

"이 이미지를 어떤 모델이 만들었는가"를 맞히는 분야가 실제로 있다(*Which Model Generated This Image?*, ECCV 2024).

**그런데 조사에서 반복적으로 확인된 한계가 우리 상황을 정면으로 때린다.**

> 초기 연구는 **closed-set** 분류에 집중했다 — 테스트에서 만나는 생성기가 전부 학습 시점에 알려져 있다고 가정한다. 그러나 새 생성 모델이 계속 나오므로 이 가정은 현실성이 낮다. 기존 방법 대부분은 **학습 때 본 모델로만 귀속할 수 있고, 새 생성기를 만나면 재학습이 필요하다.** ★

**본 대회는 운영측 생성기가 비공개다.** 4계열로 학습한 분류기에 5번째 계열이 들어오면 넷 중 하나로 잘못 배정하고, 그 뒤 단계가 통째로 어긋난다. **분류 오류가 판정 오류로 전파된다.**

대응 연구도 있다 — open-set 거부 클래스(*Progressive Open Space Expansion*), 에너지 기반 거부(*Face-Trace*), 검색 기반 귀속(재학습 불요). 다만 검색 기반은 추론 시 조회가 필요해 **규정 검토가 필요하다**(§4).

→ **결론: 계열 분류를 "쓰지 마라"가 아니라 "판정 경로에 두지 마라".** 사용법은 §3.2.

### 2.2 ② 농업적 특성 오류 모델 → **Semantic Anomaly Detection.** 있다. 그리고 **농업 도메인은 비어 있다**

*Semantic Visual Anomaly Detection and Reasoning in AI-Generated Images* (ICLR 2026)가 정확히 이 축이다.

> 많은 AI 생성 이미지는 **비현실적 물체 배치, 물리 법칙 위반, 상식 불일치** 같은 미묘한 의미적 이상을 보인다. 저수준 아티팩트가 아니라 **사람이 직접 볼 수 있고 사람의 판단과 정렬되는 내용 수준의 이상**에 초점을 둔다. ★

즉 **원안 ②는 이름이 있는 정식 연구 방향이다.** 기획서에 "의미적 이상 탐지(semantic anomaly detection)를 농업 도메인에 특화한다"고 쓸 수 있다.

**그리고 세 가지 이유로 본 대회에서 특별히 강하다.**

1. **미지 생성기 문제를 원리적으로 우회한다.** 이 브랜치는 *가짜의 흔적*이 아니라 *진짜 작물이 지켜야 할 규칙*을 배운다. **실제 이미지만으로 학습할 수 있다.** 운영측이 어떤 생성기를 썼든 무관하다.
2. **후처리에 강하다.** JPEG 재압축·리사이즈는 저수준 흔적을 지우지만 잎맥 구조를 바꾸지 못한다.
3. **농업해석상(25만원)과 발표평가 30점에 직결된다.** 공고문 p.9는 *"모델 결과에 대한 농업적 해석"* 을 명시적 평가항목으로 둔다. 팀원 절반 이상이 농업 전공인 우리 팀의 구조적 강점이 정확히 여기서 점수가 된다.

**계량화 가능한 단서가 실제로 있다.** 잎맥은 임의 그물이 아니라 **제약된 계층 네트워크**다 — 통수 효율·증산 효율·손상 내성이 구조를 제약하고, 속(clade) 안에서 전형적 계층 패턴을 공유한다. 정량 지표도 확립돼 있다: 잎맥을 **무방향 그래프로 추출해 네트워크 특징을 계산**하는 파이프라인이 있고, 전형적 피자엽에서 **세맥이 전체 잎맥 길이의 80% 이상**을 차지한다는 식의 규칙성이 알려져 있다. ★

> **생성 모델이 잎맥의 위상(topology)까지 지키기는 어렵다.** 그래프 특징(분기 차수 분포, 폐루프 비율, 세맥 길이 비율)이 실제 분포에서 벗어나면 그것이 이상 스코어가 된다. **잎맥 계량화를 AI 이미지 판별에 적용한 선행 연구는 조사 범위에서 발견되지 않았다** — 이것이 우리 팀의 novelty 주장 근거다.

**주의 하나**: 위 semantic anomaly 연구들은 대부분 **MLLM(멀티모달 LLM)** 을 쓴다. Colab 자원과 가중치 제출 의무를 생각하면 그대로 못 쓴다. **우리는 경량 자체 구현으로 간다**(그래프 특징 + 시설 구조물 직선성·주기성 + real-only 이상탐지).

### 2.3 누끼(작물만 분리) → **AIGI 탐지의 표준 접근으로는 존재하지 않는다**

객체 영역만 잘라 판별하는 방식은 조사에서 확립된 계보를 찾지 못했다. 오히려 반대 방향의 근거가 있다 — 배경("stuff")과 객체("thing")의 **관계**가 판별에 기여한다는 것이 컴퓨터 비전의 일반적 관찰이다.

그리고 본 대회에는 구체적 이유가 하나 더 있다. **공고문 유형 ②는 "현장 작물 + 다른 현장 배경"이라 작물 픽셀이 진짜 사진이다.** 누끼로 작물만 남기면 남는 것이 진짜 픽셀뿐이라, 어떤 분류기를 붙여도 "real"이 나온다. 유형 ①도 판별 근거는 작물 내부가 아니라 **작물과 배경의 불일치**(조명 방향·색온도·노이즈 레벨·초점·압축 이력)에 있다.

→ **누끼를 버리라는 뜻이 아니다. 누끼가 필요한 곳은 ② 농업 브랜치다** — 작물 형태를 보려면 작물을 분리해야 한다. **문제는 누끼를 파이프라인 맨 앞에 두어 ① 브랜치까지 통과시키는 것이다.** 위치만 옮기면 원안이 그대로 산다(§3.1).

## 3. 원안에서 고칠 두 가지

### 3.1 누끼의 위치 — 맨 앞 → 농업 브랜치 앞

```
[원안]   이미지 → 누끼 → ①생성흔적 + ②농업특성 → 가중합
                   ↑ ①이 배경을 못 보게 된다

[수정]   이미지 ┬→ ① 생성 흔적 탐지        (원본 전체를 본다)
              └→ 누끼 → ② 농업 특성 검사   (작물만 본다)
              → 가중합
```

브랜치가 둘이고 가중합으로 합친다는 **원안의 뼈대는 그대로다.** 누끼도 그대로 쓴다. 순서만 바꿨다.

### 3.2 계열 분류의 사용 방식 — 하드 라우팅 → 병렬 점수

```
[원안]   계열 분류 → 그 계열의 판별 모델만 실행
                    ↑ 분류가 틀리면 통째로 어긋난다 (§2.1 closed-set 문제)

[수정]   계열별 지표를 전부 병렬로 실행 → 점수를 그대로 가중합에 넣는다
         계열 분류 결과는 "설명 출력"으로만 쓴다 (발표평가용)
```

미지 생성기가 들어와도 오라우팅이 없다. 계열 지식은 **어떤 지표를 만들지 설계하는 데** 쓰고, **런타임 분기에는 쓰지 않는다.**

## 5. 방안 A ~ D

원안의 **두 브랜치 + 가중합** 뼈대는 네 안 모두 유지한다. 차이는 **누끼의 위치**와 **커버리지 폭**이다.

### 방안 A — 원안 그대로

```
이미지 → 누끼 → [계열 4분류 → 계열별 판별] + [농업 특성] → 가중합 → 판정
```

| | |
|---|---|
| 규정 | ✅ (YOLO만 Apache 계열로 교체) |
| 자원 | ⚠️ 모델 6개. Colab 추론 예산 초과 위험 |
| 성능 | ❌ **유형 ①②를 원리적으로 놓친다.** 배점의 최대 절반 |
| 기획서 | 구조는 명료하나 심사위원이 "합성형은 어떻게 잡나"를 물으면 답이 없다 |

### 방안 B — 누끼를 농업 브랜치로 한정 (원안 최소 수정)

```
이미지 ┬→ ① 생성 흔적 (원본 전체, 계열별 지표 병렬)
      └→ 누끼 → ② 농업 특성 오류
      → 가중합 → 판정
```

| | |
|---|---|
| 규정 | ✅ |
| 자원 | ✅ 중간 |
| 성능 | ⭕ 유형 ③④ 강함. **①②는 부분적** (배경을 보긴 하지만 영역 대조는 없음) |
| 기획서 | 원안의 형태를 유지하면서 결함만 제거. **설명이 가장 쉽다** |

### 방안 C — B + 마스크 재사용으로 영역 대조 추가 ⭐

```
이미지 ┬→ ① 생성 흔적 (원본 전체, 계열별 지표 병렬)
      ├→ ③ 영역 대조 (마스크 안/밖 노이즈·색온도·초점·조명·압축 이력 차이)
      └→ 누끼 → ② 농업 특성 오류
      → 가중합 → 판정
```

**핵심**: 누끼로 만든 마스크를 **버리지 않고 한 번 더 쓴다.** 같은 마스크가 ②에서는 "작물을 잘라내는" 용도, ③에서는 "안팎을 대조하는" 용도다. **분할 비용은 1회인데 브랜치가 둘.**

| | |
|---|---|
| 규정 | ✅ |
| 자원 | ⚠️ B보다 약간 증가 (특징 계산만, 모델 추가 없음) |
| 성능 | ✅ **유형 ①②③④ 전부 커버.** 네 안 중 최대 |
| 기획서 | *"작물 분할을 잘라내기가 아니라 영역 정의에 쓴다"* 가 차별화 문장이 된다 |

### 방안 D — 최소 구성 (안전빵 / 폴백)

```
이미지 ┬→ 전역 판별 모델 1개
      └→ 누끼 → 농업 특성 오류
      → 가중합 → 판정
```

| | |
|---|---|
| 규정 | ✅ |
| 자원 | ✅ 가장 가벼움 |
| 성능 | ⭕ 무난. 상한은 낮다 |
| 용도 | **온라인대회 1주차에 제출 규격을 먼저 통과시키는 용도.** 미제출 0점(p.7) 위험을 최우선 제거. 자원이 부족한 것으로 판명되면 최종안으로 승격 |

## 7. 권고

**C를 최종 목표로 두고, D로 먼저 제출 규격을 통과시킨 뒤 C로 올린다.**

이유는 세 가지다.

1. **C는 원안의 뼈대를 하나도 버리지 않는다.** 두 브랜치, 누끼, 가중합, 농업 특성 — 전부 그대로다. 누끼의 위치를 옮기고, 그 마스크를 한 번 더 쓰는 것이 전부다.
2. **유형 ①②는 다른 어떤 브랜치도 못 잡는다.** 테스트셋 기여도가 최대 절반이므로 여기서 막히면 상한이 생긴다.
3. **농업 특성 브랜치(원안 ②)가 이 팀의 진짜 무기다.** 미지 생성기에 원리적으로 강하고, 후처리에 강하고, 발표평가와 특별상에 직결된다. **어느 안을 택하든 이 브랜치는 반드시 넣는다.**

계열 구분(원안 ①)은 **판정 경로가 아니라 설계 근거와 설명 출력으로** 쓴다 — 어떤 지표를 만들지는 계열 지식에서 유도하되, 런타임에 계열을 맞혀서 분기하지는 않는다.
