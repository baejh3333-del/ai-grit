### R2. 생성 계열 3분류와 계열별 탐지 단서 — 기획서 문구에 직접 들어감

**왜** — 통화의 "디퓨전 / 플로우 매칭 / GAN 세 계열, 계열마다 성질이 다르니 계열별로 탐지" 논리는 `02`의 브랜치 분리 설계와 정확히 같은 논리다. 그런데 **현재 문서에는 플로우 매칭이 빠져 있고, 이건 실수다.** `03`이 생성기로 지목한 SD3와 FLUX가 rectified flow 계열이므로, 문서가 "LDM 계열"이라고 뭉뚱그린 그룹 안에 성질이 다른 두 계열이 섞여 있다. LOGO CV의 그룹 분할이 잘못 잡힐 수 있다.

**답해야 할 질문**

- (a) rectified flow / flow matching(SD3, FLUX) 생성물의 저수준 통계가 DDPM·DDIM 계열과 다른가? 통화에서 설명한 "노이즈에서 출발하니 고주파가 남는다"는 논리가 flow matching에도 그대로 성립하는가?
- (b) DDPM 계열로 학습된 탐지기가 flow matching 생성물에 일반화되는가? (LOGO CV 그룹을 몇 개로 나눌지가 여기서 결정)
- (c) **생성기 품질과 탐지 난이도의 관계** — 통화의 "비싼 모델로 만든 걸 싼 모델로 구별할 수 있나"에 대한 답. 고품질 생성기일수록 탐지가 어려워지는가, 아니면 아티팩트의 *종류*만 바뀌는가?
- (d) GAN의 스펙트럼 피크·체커보드 단서가 2026년에도 유효한가 (겐이 사실상 사장됐다면 학습 데이터 배분을 줄여야 한다)

**조사 방법**

1. arXiv / Google Scholar 검색어:
   - `rectified flow generated image detection`
   - `flow matching artifacts frequency spectrum`
   - `FLUX SD3 synthetic image detection generalization`
   - `detector generalization diffusion to flow matching`
2. `99` 참고문헌의 서베이 2편(*Is AI Generated Image Detection a Solved Problem?*, *Methods and Trends…*)의 **인용 논문을 역추적**해 2026년 이후 후속 연구 확인
3. **NTIRE 2026 챌린지 리포트(`99`에 등재)의 생성기 42종 목록을 확보**해 계열별로 분류하고, 리포트에 계열별 난이도 수치가 있으면 그대로 인용
4. FerretNet·SPAI 논문의 평가 생성기 목록에 flow matching 계열이 포함됐는지 확인 — 없으면 두 모델의 벤치마크 수치는 우리 조건에서 근거가 약해진다

**놓치지 말 것 — VAE는 계열 공통이다.** SD1.5·SDXL·SD3·FLUX가 모두 latent 공간을 쓰므로 **VAE 디코더 지문은 계열과 무관하게 남을 수 있다.** 이는 AEROBLADE(B4)의 우선순위를 5순위에서 올릴 근거가 될 수 있다. 조사에서 이 점을 확인할 것.

**산출물** `계열 × 아티팩트 단서 × 후처리 강건성` 매트릭스 → `02` §3에 추가, `03` §2.2의 LOGO 그룹 분할을 3계열(diffusion / flow matching / GAN) + 편집·합성으로 재정의

**소요** 문헌 조사 3~4시간 · **마감: 기획서용 요약은 9/9, 심화는 9/18**

### R3. 고전적(학습 불요) 방법의 실측 유효성 — **직접 실험으로 판정**

**왜** — 통화("자원 없으면 고전이 낫다")와 `02` §2.2("저수준 단서는 취약")가 정면으로 상충한다. 문헌만으로는 결론이 안 난다. 우리 도메인·우리 생성기에서 직접 재보는 것이 유일한 답이다. **그리고 이 실험 결과 표 하나를 기획서에 넣으면 공고문 p.6이 요구하는 "팀이 실제로 설정한 가설"의 증거가 된다.** 다른 팀의 계획서와 벌어지는 지점이다.

**실험 설계 (최소 규모, 반나절)**

```
데이터: real 100장(AI Hub 또는 자체 촬영) + fake 100장(SDXL로 즉석 생성)
특징(전부 학습 불요):
  F1  FFT radial power spectrum 기울기 / 고주파 대역 에너지비
  F2  DCT 계수 히스토그램 통계
  F3  고역통과 잔차(노이즈)의 분산·첨도
  F4  RGB 채널 간 상관, 색채널별 노이즈 비대칭
  F5  JPEG 8x8 블록 그리드 강도
측정: 각 특징 단독 AUC
```

**핵심은 강건성 스윕이다** — 원본이 아니라 열화 후 수치가 실전 값이다.

| 조건 | F1 AUC | F2 | F3 | F4 | F5 |
|---|---|---|---|---|---|
| 원본(PNG) | | | | | |
| JPEG QF 95 | | | | | |
| JPEG QF 80 | | | | | |
| JPEG QF 60 | | | | | |
| 리사이즈 0.5× 후 QF 90 | | | | | |

**판단 기준**
- QF 80에서 AUC ≥ 0.75 유지 → 고전 단서에 비중을 준다. 통화의 조언이 맞다
- QF 80에서 AUC < 0.6으로 붕괴 → `02` §2.2가 맞다. B1(의미 특징)·B3(영역 대조) 비중을 올린다
- **어느 쪽이든 이 표가 브랜치 가중치 초기값의 근거가 된다**

**주의** real은 JPEG, fake는 PNG로 두고 재면 압축 여부를 재는 것이지 진위를 재는 게 아니다(`02` §2.2 한계 6). **양쪽에 동일한 열화를 대칭 적용한 뒤 측정할 것.**

**소요** 데이터 확보 후 4~6시간 · **마감: 9/18 (기획서에 넣을 수 있으면 9/9지만 데이터 리드타임상 어려움)**

### R4. MoE / 작물 종별 전문가 구조 채택 여부

**왜** — 통화의 제안이고 문서에 없다. 다만 **성립 조건이 "작물 종이 한정된다"이며, 공고문은 "시설작물"이라고만 쓰고 종을 명시하지 않는다**(p.3~4 전수 확인함). 종 구성은 9/18 개막설명회에서 안내된다. 따라서 지금은 **조건부 설계**로만 준비한다.

**답해야 할 질문**
- 포렌식에서 content-conditioned 탐지기가 실제로 이득이 있는가, 아니면 데이터만 쪼개서 손해인가?
- 종별 전문가 K개 = **제출 용량 K배**. 공고문 p.5는 모든 가중치 제출을 요구하고 p.4는 Colab 자원 범위를 요구한다 → 정면 충돌 가능
- 용량을 안 늘리는 대안이 있는가?

**조사 방법**
1. 검색어: `mixture of experts image forensics`, `content-aware deepfake detection`, `domain-specific synthetic image detector`, `conditional adapter forgery detection`
2. **대안 설계 조사에 무게를 둘 것** — 전체 모델 K개가 아니라:
   - 공유 백본 + 종별 LoRA/어댑터 헤드 (종당 수 MB)
   - 종 임베딩을 FiLM 등으로 조건 주입하는 단일 모델
   - 라우터를 별도 모델이 아니라 백본 특징 재활용으로 구현
3. 라우터 오류의 전파 비용 계산 — `02` §2.2 한계 3·4와 같은 함정이다. **라우터가 틀리면 잘못된 전문가로 가고, 라우터는 실제 이미지로 학습되므로 생성 이미지에서 정확도가 다를 수 있다.** 이 편향이 분류로 새는 경로를 반드시 검토

**판단 기준**
- 종 수 ≤ 5 **and** 라우터 정확도 ≥ 95% **and** 종별 학습 데이터 충분 → 어댑터 방식 채택
- 그 외 → 단일 모델 + 종 임베딩 조건 주입, 또는 미채택
- **기획서에는 "종 구성이 확정되면 종별 어댑터로 전환"이라는 조건부 한 문장으로만 넣는다.** 확정 안 된 것을 확정처럼 쓰면 오히려 감점이다

**소요** 2~3시간 · **마감: 판단은 9/18 이후, 기획서 문구는 9/9**

### R5. 융합·캘리브레이션·임계값

**왜** — 통화안(가중합 + 임계값)과 문서안(로지스틱 회귀 + 캘리브레이션)의 정렬. 방향은 같고 문서안이 상위호환이라 큰 조사는 불필요하다. 다만 **임계값의 중요도가 평가지표에 따라 완전히 달라진다.**

**답해야 할 질문**
- 평가지표가 AUC면 임계값은 무의미. Accuracy·F1이면 임계값이 점수를 지배한다 → **9/18 최우선 확인 항목** (`03` §5에 이미 등재됨)
- 브랜치 하나가 실패(세그멘테이션 실패 등)할 때 융합기의 결측 처리
- 캘리브레이션: Platt scaling vs isotonic regression, 검증셋 크기 요구량

**조사 방법** 문헌 조사 최소화. scikit-learn `CalibratedClassifierCV` 문서 + 스태킹 일반론이면 충분

**소요** 2시간 · **마감: 온라인대회 3주차**

### R6. 농학적 해석의 계량화 가능 범위 (발표 30점 + 농업해석상)

## 6. 통화 내용 중 문서에 반영하지 않을 것

- **"작물만 누끼 따서 고주파 분석"** — `02` §2.1에서 유형 ①②에 원리적으로 실패한다고 판정됨. 세그멘테이션은 **영역 대조용**으로 용도를 바꿔 유지한다(B3). 통화에서도 "따는 게 코스트가 더 든다"는 지적이 나왔고, 결론은 같은 방향이다.
- **GPT/외부 API에 이미지와 점수를 넣어 판정** — 통화에서 언급 후 규정상 불가로 정정됨. 추론 단계 외부 API는 p.5·p.10 위반이고, 대회 이미지를 외부에 올리면 p.9 위반이다. **개발 단계에서도 대회 제공 이미지는 외부 서비스에 올리지 않는다.**
- **단순 가중합 + 고정 임계값** — 로지스틱 회귀 + 캘리브레이션의 하위호환. 다만 **검증 데이터가 부족할 때의 폴백**으로는 남겨둔다(과적합 위험이 더 낮다).
