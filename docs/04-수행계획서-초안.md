## 2. 문제에 대한 이해 및 핵심 아이디어

### 2.1 문제의 성격

공고문이 정의한 생성 이미지는 네 유형이다 — ① 실험실 작물+현장 배경 합성, ② 현장 작물+다른 현장 배경 합성, ③ 스타일 변환, ④ 전체 생성.
이 중 **①②는 이미지의 대부분이 실제 촬영 픽셀인 "부분 합성"** 이고, ③④는 전역 변환이다. 즉 본 미션은 단일한 생성 이미지 탐지 문제가 아니라 **전역 생성 탐지와 부분 위조 탐지가 결합된 문제**다.

이 구분이 중요한 이유는, 유형 ①②에서 **판별 근거가 작물 자체가 아니라 작물과 배경의 불일치**(조명 방향, 색온도, 노이즈 레벨, 초점, 그림자, JPEG 압축 이력)와 **경계의 블렌딩 흔적**에 있기 때문이다. 작물 영역만 잘라내어 분석하는 접근은 유형 ②에서 진짜 픽셀만 남기게 되어 원리적으로 실패한다. 따라서 우리 팀은 **분할 마스크를 "잘라내기"가 아니라 "영역 간 통계 대조"에 사용**한다.

### 2.2 핵심 가설 — "가짜를 배우지 말고 진짜를 배운다"

본 대회의 근본 난제는 **운영측이 사용한 생성 모델이 비공개**라는 점이다. 우리가 만든 생성 데이터로만 지도학습하면 그 생성기에 과적합되고, 운영측이 다른 계열을 썼을 때 그대로 무너진다.

그래서 우리는 가짜의 특징이 아니라 **실제 이미지의 정상성**을 학습하는 축을 병행한다. 본 대회는 이 접근에 유리한 두 조건을 갖는다 — **콘텐츠가 시설작물이라는 좁은 단일 도메인**이고, **실제 이미지를 대량 확보할 수 있다**(AI Hub 스마트팜 데이터). 넓은 도메인에서는 정의하기 어려운 "정상 분포"를 우리는 정밀하게 모델링할 수 있다. 실제 시설작물 이미지만으로 자기지도 학습한 스펙트럼·국소 픽셀 통계의 정상 모델을 세우고, 이로부터의 이탈을 이상 스코어로 사용해 미지 생성기 문제를 우회한다.

### 2.3 두 번째 원칙 — 저수준 흔적을 훼손하지 않는다

생성 흔적은 미세한 고주파에 남는데, 리사이즈는 보간을 수반해 이를 지운다. 따라서 전 과정에서 **리사이즈 대신 원본 해상도 크롭**을 사용한다. 또한 자체 생성 이미지는 PNG, 수집 실제 이미지는 JPEG가 되기 쉬워 모델이 "진위"가 아닌 "압축 여부"를 학습할 위험이 있으므로, **실제·생성 양쪽에 동일한 무작위 압축·리사이즈·블러 증강을 대칭 적용**해 이 지름길을 차단한다.

## 3. 이미지 미션 수행전략

유형별 전문가를 두고 결과를 융합한다. 이질적인 위조 유형을 단일 분류기에 통합하면 특성 공간이 겹쳐 성능이 저하되기 때문이다.

| 브랜치 | 방식 | 담당 유형 |
|---|---|---|
| B0 | 경량 CNN 기반 국소 픽셀 의존성 탐지(FerretNet, Apache-2.0, 1.06M 파라미터) 파인튜닝 | ③④ |
| B3 | **부분 합성 국소화** — RGB + 노이즈 잔차 이중 스트림 자체 학습. 작물 마스크 안/밖의 노이즈 통계·JPEG 블록 정렬·색온도·초점·조명 방향 **차이**를 특징화하고, 패치 스코어를 top-k 풀링 | **①②** |
| B1 | 동결 CLIP/DINOv2 특징 + 선형 분류기 (미지 생성기 일반화) | ③④ |
| B2 | 실제 이미지 스펙트럼 분포 자기지도 학습 후 OOD 판정 (§2.2 가설의 구현) | ③④ |

융합은 브랜치 출력에 대한 로지스틱 회귀와 확률 보정으로 수행하며, 가중치는 아래 검증 결과로 결정한다. B3가 산출하는 **위조 히트맵**은 판단 근거를 시각적으로 제시해 농업적 해석과 현장 적용성 논의에 활용한다.

## 4. AI 도구 및 데이터 활용계획

- **실제 이미지**: AI Hub 지능형 스마트팜 데이터(토마토·파프리카·오이·딸기), 시설작물(딸기) 개체·질병 이미지, 자체 촬영분. 카메라·농가·시기의 다양성을 의도적으로 확보해 특정 촬영기기에 대한 편향을 방지한다.
- **생성 이미지**: 공고문의 4유형을 그대로 재현한다. 합성형은 SAM 분할 후 알파/Poisson 블렌딩·하모나이제이션·인페인팅 융합을 난이도별로 적용하고, 스타일 변환형은 img2img·ControlNet·GAN 계열을, 전체 생성형은 SD/SDXL/FLUX 계열과 작물 도메인 LoRA를 사용한다. 동일 원본에서 가짜를 파생시켜 콘텐츠 편향을 제거한다.
- **규정 준수**: 학습 단계의 생성형 AI 도구 사용은 허용되나, **추론 단계에서는 외부 API 호출과 외부 다운로드를 일절 사용하지 않는다.** 모든 가중치를 제출물 내 로컬 경로에서 로딩하고, 네트워크를 차단한 상태에서 추론 완주를 검증한다. 사용 자산은 재배포 가능한 라이선스(Apache-2.0, MIT)로 한정하며, 외부 데이터·모델의 출처와 이용조건, 생성 방법을 최종 제출자료에 명시한다.

## 5. 추진계획 및 예상 문제·대응방안

| 기간 | 내용 |
|---|---|
| ~9/20 | 실제 이미지 풀 확보, 생성 파이프라인 구축, 예시 이미지 분석 |
| 1주차 | **베이스라인(B0)으로 제출 규격을 먼저 통과** — 미제출 0점 위험 우선 제거 |
| 2주차 | 생성 데이터 4유형 완비, B3 착수, 교차검증 체계 구축 |
| 3주차 | B1·B2 추가, 앙상블 및 확률 보정 |
| 4주차 | 강건성 점검, Colab 실행·재현성 검증, 최종 제출 |

**검증 체계**: ① 학습에 쓰지 않은 생성기로 평가하는 **Leave-One-Generator-Out 교차검증**으로 미지 생성기 대응력을 사전 추정하고, ② 특정 농가·카메라를 제외한 평가로 실제 데이터 도메인 이동 내성을 확인하며, ③ **생성 유형별 성능을 항상 분리 측정**해 전체 평균에 가려지는 취약 유형을 찾아낸다. ④ 압축률·리사이즈 배율·블러 강도에 대한 성능 곡선을 그려 절벽 구간을 보강한다. 운영측 제공 예시 이미지는 검증 전용으로만 사용한다.
