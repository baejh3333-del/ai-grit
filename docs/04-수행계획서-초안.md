## 2. 문제에 대한 이해 및 핵심 아이디어

### 2.1 판별 근거는 두 곳에 따로 있다

공고문의 생성 이미지는 네 유형이다 — ① 실험실 작물+현장 배경 합성, ② 현장 작물+다른 현장 배경 합성, ③ 스타일 변환, ④ 전체 생성. ①②는 **이미지의 대부분이 실제 촬영 픽셀인 부분 합성**이고 ③④는 전역 변환이다.

우리 팀의 출발점은 **판별 근거가 성격이 다른 두 곳에 나뉘어 있다**는 관찰이다.

- **기술적 근거** — 생성 과정이 픽셀에 남긴 흔적. 유형마다 다르고 후처리에 약하다
- **농업적 근거** — 실제 작물이라면 지켜야 할 형태·구조·생육의 규칙. 생성 모델이 자주 어기지만, 이를 판별에 쓰려면 작물을 알아야 한다

그래서 **두 축을 독립적으로 세우고 점수를 가중합**한다. 서로 다른 증거원이므로 한 축이 무너져도 다른 축이 남는다.

### 2.2 축 A — 생성 흔적을 계열의 원리에서 유도한다

단일 분류기가 모든 유형을 학습하게 두지 않는다. 이질적인 생성 방식의 아티팩트를 하나의 특성 공간에 몰아넣으면 서로 겹치며 성능이 정체된다. 대신 **생성 계열을 나누고, 각 계열이 이미지를 만드는 방식에서 지표를 직접 유도한다** — 확산-U-Net, 플로우 매칭(DiT), GAN, 오토리그레시브.

**여기서 두 가지 판단을 했다.**

**(가) 계열을 가로지르는 공통 단서가 있다.** 확산이든 플로우 매칭이든 증류든, 잠재 공간에서 생성하는 모델은 **마지막에 모두 같은 종류의 VAE 디코더를 통과한다.** 그 디코더로 재구성했을 때의 오차 하나가 네 계열을 동시에 겨냥한다. **운영측 생성기가 비공개**라는 본 대회의 근본 난제에 대한 우리의 주된 대비책이다.

**(나) 계열 분류를 판정 경로에 두지 않는다.** "어떤 모델이 만들었는가"를 맞히는 연구(model attribution)가 있으나, 대부분 **closed-set**이라 학습 때 본 생성기로만 귀속되고 새 생성기는 재학습을 요구한다. 생성기가 비공개인 본 대회에서 계열을 먼저 맞혀 분기하면 **오분류가 판정 오류로 그대로 전파된다.** 따라서 계열별 지표를 **전부 병렬로 실행해 점수를 합산**하고, 계열 추정 결과는 판단 근거를 설명하는 출력으로만 쓴다.

### 2.3 축 B — 농업적 정합성. 이 팀이기에 할 수 있는 축

*"실제 작물이라면 이럴 수 없다"* 를 판별에 쓴다. 잎맥의 위상 구조, 엽서 배열, 과실과 잎의 스케일 정합, 병징이 잎맥을 따라 번지는지, 점적관수 라인과 유인줄이 직선과 등간격을 지키는지. **잎맥은 임의의 그물이 아니라 통수 효율과 손상 내성이 제약하는 계층 네트워크**이므로, 무방향 그래프로 추출해 분기 차수 분포·폐루프 비율·세맥 길이 비율로 계량할 수 있다.

**이 축은 세 가지 이유로 본 대회에 특별히 유리하다.**

1. **미지 생성기 문제를 원리적으로 우회한다.** 가짜의 흔적이 아니라 진짜 작물이 지켜야 할 규칙을 배우므로 **실제 이미지만으로 학습된다.** 운영측이 어떤 생성기를 썼든 무관하다.
2. **후처리에 강하다.** JPEG 재압축과 리사이즈는 저수준 흔적을 지우지만 잎맥의 위상을 바꾸지 못한다. 축 A가 약해지는 구간에서 축 B가 버틴다.
3. **판단 근거를 사람의 언어로 설명할 수 있다.** "이 잎은 잎맥 분기가 실제 분포를 벗어난다"는 진술은 확률값보다 검증 가능하며, 현장 적용성 논의로 이어진다.

### 2.4 작물 분할은 한 번, 용도는 두 개

작물을 분리하되 **이미지 전체를 버리지 않는다.** 유형 ②는 작물 픽셀이 실제 촬영물이라 작물만 남기면 진짜 픽셀만 남고, 유형 ①의 근거도 작물 내부가 아니라 **작물과 배경의 불일치**(조명 방향·색온도·노이즈 레벨·초점·압축 이력)에 있기 때문이다.

그래서 분할 마스크를 **두 용도로 쓴다** — 축 B에서는 작물을 분리하는 "누끼"로, 축 A에서는 **마스크 안팎의 통계를 대조**하는 영역 정의로. **분할은 한 번만 수행하는데 판별 근거는 둘이 된다.**

### 2.5 저수준 흔적을 훼손하지 않는다

리사이즈는 보간을 수반해 미세 흔적을 지우므로 전 과정에서 **원본 해상도 크롭**을 쓴다. 또한 자체 생성 이미지는 PNG, 수집 실제 이미지는 JPEG가 되기 쉬워 모델이 "진위"가 아닌 "압축 여부"를 학습할 위험이 있으므로, **양쪽에 동일한 무작위 압축·리사이즈·블러 증강을 대칭 적용**해 이 지름길을 차단한다.

## 3. 이미지 미션 수행전략

```
입력 이미지(원본 해상도)
  ├─ 축 A · 생성 흔적 ─ A1 잠재-디코더 │ A2 스펙트럼 │ A3 양자화 │ A4 영역 대조 │ A5 전역 모델
  ├─ 작물 분할 → 마스크 M ─┬→ A4 (영역 정의)
  │                        └→ 축 B (누끼)
  ├─ 축 B · 농업 정합성 ─ B1 형태 │ B2 시설 구조물 │ B3 생육 정합
  └─ score = Σw·A + Σv·B  →  score ≥ τ 이면 생성 이미지
```

**축 A.** A1은 VAE 왕복 재구성 오차(학습 불요, 확산·플로우매칭·증류·잠재 인페인팅을 동시 담당), A2는 방사 파워 스펙트럼의 거듭제곱 감쇠 적합 잔차와 초고주파 꼬리 에너지(GAN·픽셀 확산), A3은 코드북 재양자화 오차(오토리그레시브 — 노이즈에서 출발하지 않아 A1·A2가 통하지 않는 계열), A4는 마스크 안팎의 노이즈 잔차·JPEG 블록 정렬·색온도·초점·조명 방향 **차이**를 패치별로 계산해 top-k 풀링(합성물은 대부분이 진짜이므로 전역 평균은 신호를 희석시킨다). A5는 계열 지식 없이 통째로 판단하는 경량 CNN(1.06M 파라미터, Apache-2.0) 안전망이며, **온라인대회 1주차에는 A5 단독으로 먼저 제출 규격을 통과시켜** 미제출 0점 위험을 최우선 제거한다.

**축 B.** 잎맥 그래프 특징과 시설 구조물의 직선성·주기성(Hough 직선, 자기상관 주기 피크)을 계량화하고, 실제 이미지만으로 정상 분포를 학습해 이탈을 이상 스코어로 삼는다. 대상 작물의 종 구성이 확정되기 전에는 **종에 무관하게 성립하는 시설 구조물 지표를 우선**한다.

**융합.** 가중치는 아래 검증 결과로 결정한다. 각 지표는 검증셋 기준으로 정규화한 뒤 합산하며, 지표가 침묵할 때(분할 실패 등)의 결측 규칙을 사전 정의한다. 축 A와 축 B의 배분은 별도 관리하여, 테스트 이미지가 균일 재인코딩된 것으로 확인되면 축 B 비중을 올린다. 검증 데이터가 충분하면 로지스틱 회귀와 확률 보정으로 승격하되, 부족하면 **과적합 위험이 더 낮은 가중합을 유지한다.**

**정형데이터 미션**: 〔팀 작성 — 담당 팀원이 별도 작성〕

## 4. AI 도구 및 데이터 활용계획

- **실제 이미지**: AI Hub 지능형 스마트팜 데이터(토마토·파프리카·오이·딸기), 시설작물(딸기) 개체·질병 이미지, 자체 촬영분. 카메라·농가·시기의 다양성을 의도적으로 확보해 특정 촬영기기 편향을 방지한다. **축 B의 정상 분포 학습에도 이 실제 데이터만 사용한다.**
- **생성 이미지**: 공고문 4유형을 재현하되 **계열을 명시적으로 나눠** 구성한다 — 확산-U-Net(SD1.5/SDXL), 플로우 매칭(SD3/FLUX), GAN(CycleGAN 등 도메인 변환), 편집-픽셀공간(알파/Poisson/하모나이제이션), 편집-잠재공간(인페인팅·img2img). 소수 스텝 증류 모델만 쓰면 "스텝이 적을 때의 흔적"을 배우므로 full-step 버전을 함께 섞고, 작물 도메인 LoRA로 시설 적합도를 맞춘다. **동일 원본에서 가짜를 파생**시켜 "작물 종류"가 아니라 "진위"를 학습하게 한다.
- **사전학습 모델**: 분할은 SAM 계열(Apache-2.0)을 사용한다. **AGPL 라이선스 모델은 사용하지 않는다** — 해당 라이선스가 산출 가중치까지 미치는데 공고문 p.5는 가중치 제출을 예외 없이 요구하기 때문이다.
- **규정 준수**: 학습 단계의 생성형 AI 도구 사용은 허용되나 **추론 단계에서는 외부 API 호출과 외부 다운로드를 일절 사용하지 않는다.** 모든 가중치를 제출물 내 로컬 경로에서 로딩하고 네트워크 차단 상태에서 추론 완주를 검증한다. 외부 데이터·모델의 출처와 이용조건, 생성 방법을 최종 제출자료에 명시한다.

## 5. 추진계획 및 예상 문제·대응방안

| 기간 | 내용 |
|---|---|
| ~9/20 | 컴퓨팅 자원 확정, 실제 이미지 풀 확보, 계열별 생성 파이프라인 구축 |
| 1주차 | **A5 단독으로 제출 규격 먼저 통과** — 미제출 0점 위험 제거. 예시 이미지 분석 |
| 2주차 | 계열별 생성 데이터 완비, A1·A4 구현, 축 B 착수, 교차검증 체계 구축 |
| 3주차 | A2·A3 추가, 축 B 완성, 가중합 튜닝 및 임계값 결정 |
| 4주차 | 강건성 점검, Colab 실행·재현성 검증, 최종 제출 |

**검증 체계**: ① 학습에 쓰지 않은 계열로 평가하는 **Leave-One-Generator-Out 교차검증**으로 미지 생성기 대응력을 사전 추정한다. 이때 **플로우 매칭을 확산과 같은 그룹에 두지 않는다** — 같은 그룹에 두면 계열 이동을 재려는 검증이 계열 이동을 재지 못한다. ② 특정 농가·카메라를 제외한 평가로 실제 데이터의 도메인 이동 내성을 확인한다. ③ **유형별 성능을 항상 분리 측정**하되, 유형 ①②는 **픽셀 합성분과 잠재 재생성분으로 한 단계 더 쪼개서** 본다. 합쳐 보면 한쪽의 실패가 다른 쪽에 가려지기 때문이다. ④ **축 A와 축 B의 기여도를 분리 측정**해, 압축률·리사이즈 배율에 대한 성능 곡선을 두 축 각각에 대해 그린다. 운영측 제공 예시 이미지는 검증 전용으로만 사용한다.

**예상 문제와 대응**

| 예상 문제 | 대응 |
|---|---|
