## 2. 문제에 대한 이해 및 핵심 아이디어

### 2.1 이 문제는 "생성 이미지 탐지" 하나가 아니다

공고문이 정의한 생성 이미지는 네 유형이다 — ① 실험실 작물+현장 배경 합성, ② 현장 작물+다른 현장 배경 합성, ③ 스타일 변환, ④ 전체 생성.
**①②는 이미지의 대부분이 실제 촬영 픽셀인 "부분 합성"** 이고 ③④는 전역 변환이다. 즉 본 미션은 **전역 생성 탐지와 부분 위조 탐지가 결합된 문제**이며, 판별 근거의 위치가 유형마다 다르다. ①②에서는 근거가 작물 자체가 아니라 **작물과 배경의 불일치**(조명 방향, 색온도, 노이즈 레벨, 초점, 압축 이력)에 있으므로, 작물 영역만 잘라내어 분석하는 접근은 유형 ②에서 진짜 픽셀만 남기게 되어 원리적으로 실패한다. 우리 팀이 **분할 마스크를 "잘라내기"가 아니라 "영역 간 통계 대조"에 사용**하는 이유다.

### 2.2 핵심 아이디어 — 생성 원리에서 지표를 유도한다

우리는 하나의 분류기가 모든 유형을 학습하도록 하지 않는다. 이질적인 생성 방식의 아티팩트를 단일 특성 공간에 몰아넣으면 서로 겹치며 성능이 정체된다는 것이 최근 연구의 관찰이다. 대신 **생성 계열을 먼저 나누고, 각 계열이 이미지를 만드는 방식에서 판별 지표를 직접 유도한다.**

| 지표 | 겨냥 계열 | 판별 원리 |
|---|---|---|
| **S1 잠재-디코더** | 확산·플로우 매칭·증류·잠재 인페인팅 | 잠재 생성 모델의 출력은 **예외 없이 VAE 디코더를 통과한다.** 그 디코더로 재구성하면 자기 계열 생성물을 실제 촬영 이미지보다 정확히 복원한다 |
| **S2 스펙트럼** | GAN·픽셀 확산 | 업샘플 연산이 주파수 영역에 **스펙트럼 복제**를 남기고, 생성 이미지는 자연 이미지의 **고주파 감쇠 곡선을 재현하지 못한다** |
| **S3 영역 대조** | 유형 ①② 중 픽셀 공간 합성 | 픽셀 합성은 배경을 건드리지 않으므로 **작물 영역 안팎의 통계가 어긋난다** |
| **S4 양자화** | 오토리그레시브 | **유한 코드북 양자화 오차**의 구조가 실제 이미지와 다르다 |

**여기서 우리 팀의 두 가지 판단이 갈린다.**

**(가) 계열을 셋이 아니라 넷으로 나눈다.** 이미지 생성의 주류는 확산·플로우 매칭·GAN 세 계열로 이야기되지만, 최근 주력 모델(SD3, FLUX)은 확산이 아니라 **플로우 매칭(rectified flow)** 계열이다. 확산이 노이즈 주입의 역과정을 곡선 궤적으로 학습한다면, 플로우 매칭은 노이즈와 데이터를 **직선으로 잇는 속도장**을 학습한다. 궤적과 스케줄이 다르므로 확산 출력에 맞춰 학습한 저수준 탐지기는 그대로 옮겨가지 않는다. 여기에 **오토리그레시브 계열**(토큰 예측 방식, 최근 상용 도구가 이쪽으로 이동)은 애초에 노이즈에서 출발하지 않아 저수준 단서 논리가 원리적으로 통하지 않는다. 따라서 우리는 계열을 넷으로 두고 **검증 시에도 계열을 분리**한다.

**(나) 그런데 계열을 가로지르는 공통 단서가 하나 있다.** 확산이든 플로우 매칭이든 증류든, 잠재 공간에서 생성하는 모델은 **마지막에 모두 같은 종류의 VAE 디코더를 통과한다.** 즉 **지표 하나(S1)가 네 계열을 동시에 겨냥한다.** 이것이 우리가 S1을 1순위에 두는 이유이며, 운영측 생성기가 비공개라는 본 대회의 근본 난제에 대한 우리의 주된 대비책이다.

**(다) 그리고 이 성질은 유형 ①②의 절반을 S1이 담당한다는 뜻이기도 하다.** 잠재 공간 인페인팅으로 만든 합성 이미지는 마스크 바깥의 바뀌지 않은 영역까지 포함해 **이미지 전체가 재디코딩된다.** 그 결과 카메라 수준의 노이즈 패턴이 전역에서 균일해져 **영역 간 대조 신호가 사라진다.** 반대로 알파·Poisson 블렌딩 같은 픽셀 공간 합성은 배경을 그대로 두므로 불일치가 남는다. 따라서 **S3는 픽셀 공간 합성분을, S1은 잠재 공간 재생성분을 나눠 담당하며, 둘 중 하나만으로는 유형 ①②의 절반만 잡는다.**

### 2.3 두 번째 원칙 — 저수준 흔적을 훼손하지 않는다

생성 흔적은 미세한 고주파에 남는데, 리사이즈는 보간을 수반해 이를 지운다. 따라서 전 과정에서 **리사이즈 대신 원본 해상도 크롭**을 사용한다. 또한 자체 생성 이미지는 PNG, 수집 실제 이미지는 JPEG가 되기 쉬워 모델이 "진위"가 아닌 "압축 여부"를 학습할 위험이 있으므로, **실제·생성 양쪽에 동일한 무작위 압축·리사이즈·블러 증강을 대칭 적용**해 이 지름길을 차단한다.

## 3. 이미지 미션 수행전략

**구조: 계열별 전문 지표 4종 + 전역 판별 모델 → 가중합 → 임계값 판정**

```
입력 이미지(원본 해상도)
  ├─[0] 작물 종 라우팅 (종 구성 확정 시)  → 종별 어댑터
  ├─[1] 계열별 지표      S1 잠재-디코더 / S2 스펙트럼 / S3 영역 대조 / S4 양자화
  ├─[2] 전역 판별 모델   S5 이미지를 통째로 입력받는 학습 기반 이진 분류
  └─[3] score = Σ wᵢ·Sᵢ  →  score ≥ τ 이면 생성 이미지
```

**[1] 계열별 지표.** S1은 VAE 왕복 재구성 오차(학습 불요), S2는 방사 파워 스펙트럼의 거듭제곱 감쇠 적합 잔차와 초고주파 꼬리 에너지, S3는 작물 마스크 안/밖의 노이즈 잔차·JPEG 블록 정렬·색온도·초점·조명 방향 **차이**를 특징화하고 패치 스코어를 top-k 풀링한다(합성물은 대부분이 진짜이므로 전역 평균은 신호를 희석시킨다). S4는 자원 여유 시 추가한다. S3가 산출하는 **위조 히트맵**은 판단 근거를 시각적으로 제시해 농업적 해석에 활용한다.

**[2] 전역 판별 모델.** 계열 지식 없이 이미지를 통째로 판단하는 안전망으로, 경량 CNN 기반 국소 픽셀 의존성 탐지 모델(1.06M 파라미터, Apache-2.0)을 파인튜닝하고 동결 CLIP/DINOv2 선형 분류기를 보조로 둔다. **온라인대회 1주차에는 이 모델 단독으로 먼저 제출 규격을 통과시켜** 미제출 0점 위험을 최우선으로 제거한다.

**[3] 가중합.** 가중치 wᵢ는 아래 검증 결과로 결정한다. 특정 계열을 학습에서 제외했을 때 어떤 지표가 그 계열을 붙잡는지가 그대로 가중치의 근거가 된다. 각 지표는 검증셋 기준으로 정규화한 뒤 합산하며, 지표가 침묵할 때(분할 실패 등)의 결측 처리 규칙을 사전에 정의한다. 검증 데이터가 충분하면 로지스틱 회귀와 확률 보정으로 승격하되, 부족하면 **과적합 위험이 더 낮은 가중합을 유지한다.**

**[0] 작물 종 라우팅.** 대상 작물의 종 구성이 확정되면, 종을 먼저 분류하고 해당 종의 전문 어댑터로 라우팅한다. 다만 **전체 모델을 종별로 복제하지 않는다** — 제출 용량이 종 수만큼 배가되어 Colab 자원 제약과 충돌하기 때문이며, 공유 백본에 종별 경량 어댑터만 얹는다. 라우터가 생성 이미지에서 오분류할 위험이 있으므로 **전역 어댑터로의 폴백**을 둔다.

**정형데이터 미션**: 〔팀 작성 — 담당 팀원이 별도 작성〕

## 4. AI 도구 및 데이터 활용계획

- **실제 이미지**: AI Hub 지능형 스마트팜 데이터(토마토·파프리카·오이·딸기), 시설작물(딸기) 개체·질병 이미지, 자체 촬영분. 카메라·농가·시기의 다양성을 의도적으로 확보해 특정 촬영기기에 대한 편향을 방지한다.
- **생성 이미지**: 공고문 4유형을 재현하되 **계열을 명시적으로 나눠** 구성한다 — 확산-잠재(SD1.5/SDXL), 플로우 매칭(SD3/FLUX), GAN(CycleGAN 등 도메인 변환), 편집-픽셀공간(알파/Poisson/하모나이제이션), 편집-잠재공간(인페인팅·img2img). 소수 스텝 증류 모델만 쓰면 "스텝이 적을 때의 흔적"을 배우게 되므로 full-step 버전을 함께 섞고, 작물 도메인 LoRA로 시설 적합도를 맞춘다. **동일 원본에서 가짜를 파생**시켜 "작물 종류"가 아니라 "진위"를 학습하도록 한다.
- **규정 준수**: 학습 단계의 생성형 AI 도구 사용은 허용되나, **추론 단계에서는 외부 API 호출과 외부 다운로드를 일절 사용하지 않는다.** 모든 가중치를 제출물 내 로컬 경로에서 로딩하고, 네트워크를 차단한 상태에서 추론 완주를 검증한다. 사용 자산은 재배포 가능한 라이선스(Apache-2.0, MIT)로 한정하며, 외부 데이터·모델의 출처와 이용조건, 생성 방법을 최종 제출자료에 명시한다.

## 5. 추진계획 및 예상 문제·대응방안

| 기간 | 내용 |
|---|---|
| ~9/20 | 컴퓨팅 자원 확정, 실제 이미지 풀 확보, 계열별 생성 파이프라인 구축 |
| 1주차 | **전역 모델(S5) 단독으로 제출 규격 먼저 통과** — 미제출 0점 위험 우선 제거. 예시 이미지 분석 |
| 2주차 | 계열별 생성 데이터 완비, S1·S3 구현, 교차검증 체계 구축 |
| 3주차 | S2·S4 추가, 가중합 튜닝 및 임계값 결정 |
| 4주차 | 강건성 점검, Colab 실행·재현성 검증, 최종 제출 |

**검증 체계**: ① 학습에 쓰지 않은 계열로 평가하는 **Leave-One-Generator-Out 교차검증**으로 미지 생성기 대응력을 사전 추정한다. 이때 **플로우 매칭을 확산과 같은 그룹에 두지 않는다** — 같은 그룹에 두면 계열 이동을 재려는 검증이 계열 이동을 재지 못한다. ② 특정 농가·카메라를 제외한 평가로 실제 데이터 도메인 이동 내성을 확인한다. ③ **유형별 성능을 항상 분리 측정**하되, 유형 ①②는 **픽셀 합성분과 잠재 재생성분으로 한 단계 더 쪼개서** 본다. 합쳐 보면 한쪽의 실패가 다른 쪽 성능에 가려지기 때문이다. ④ 압축률·리사이즈 배율·블러 강도에 대한 성능 곡선을 그려 절벽 구간을 보강한다. 운영측 제공 예시 이미지는 검증 전용으로만 사용한다.
