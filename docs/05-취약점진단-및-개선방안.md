## 1. 배점 구조 취약점 — 가장 큰 구멍

### V1·V2. 40점짜리 미션이 통째로 비어 있다

현재 `README.md`는 *"이 저장소는 이미지 미션만 다룬다. 정형데이터 미션은 범위 밖"* 이라고 선언한다. 그런데 공고문의 배점은 반대 방향이다.

- 온라인 정량평가 70점 = **정형 40점** + 이미지 30점 (p.1, p.7)
- 현장 발표팀(최대 10팀) 선정 동점 시 우선순위: **정형데이터 미션 점수 → 이미지 미션 점수** (p.8)
- 최종 종합점수 동점 시: 온라인 총점 → **정형데이터 미션 점수** → 이미지 미션 점수 (p.9)
- 특정 미션 미제출 시 해당 미션 **0점** (p.7)

즉 **배점에서도, 두 단계의 동점 처리 규칙에서도 정형이 이미지보다 우선한다.** 이미지 미션을 완벽하게 수행해도 상한은 30 + 30(발표) = 60점이고, 정형이 0점이면 현장 발표팀 10팀 안에 드는 것 자체가 어렵다.

**개선 방안 — 정형 미션의 최소 실행 설계 (공고문 정보만으로 지금 확정 가능한 부분)**

공고문 p.4~5가 이미 밝힌 구조가 결정적이다.

> `train_X`는 실제 농가 데이터를 기반으로 **일부 값 또는 구간에 생성 데이터가 혼입된 형태**로 구성하며, `train_y`는 이에 대응하는 **실제 관측 기반 목표값**으로 구성. `test_X`는 **생성 데이터가 혼입되지 않은** 실제 농가 데이터.

이것은 단순 회귀 문제가 아니라 **학습 입력에만 오염이 있고 테스트 입력은 깨끗한 비대칭 분포이동 문제**다. 그리고 이 구조는 이미지 미션의 "신뢰성 판별"과 정확히 같은 주제다 — 즉 팀의 핵심 가설을 두 미션에 일관되게 적용할 수 있다(발표평가·특별상에 유리).

| 단계 | 방법 | 근거 |
|---|---|---|
| ① 혼입 구간 탐지 | `train_X` vs `test_X` **adversarial validation** (두 집합을 판별하는 분류기를 학습해 판별 가능한 행·구간·변수를 식별) | test_X는 클린이므로 판별 가능한 행이 곧 혼입 후보 |
| ② 물리 정합성 검사 | 온도·습도→VPD 정합, 일사량과 온도 상승의 시간 지연, 야간 광량 0, CO₂와 환기 제어의 인과 방향, 센서 값의 물리적 상·하한 및 변화율 한계 | 생성 데이터는 변수 **간** 결합분포에서 먼저 무너진다 |
| ③ 시계열 이상 구간 | 구간 단위(rolling window) 이상 스코어 — 자기상관 붕괴, 계단형 점프, 분산 급변 | 공고문이 "일부 값 **또는 구간**"이라 명시 |
| ④ 대응 | 혼입 의심 표본 **가중치 하향(soft) / 제거(hard)** 두 안을 GroupKFold로 비교 | 무조건 제거는 데이터 손실 |
| ⑤ 모델 | 그래디언트 부스팅 계열 + robust loss(Huber/Quantile) 기준선, 시계열 특징(lag·rolling) 추가 | test는 CSV 제출 자동평가(p.5) |
| ⑥ 검증 | **농가·시기 단위 GroupKFold** (여러 농가·환경·시기 자료 사용이 p.3·p.4에 명시) | 무작위 KFold는 시계열 누수로 과대평가된다 |

목표 변수와 지표는 개막설명회에서 확정되므로(p.5), 위 ①~④는 **목표 변수와 무관하게 지금 설계·구현 가능하다.** 이것이 D-3 시점에 정형 미션 공백을 메우는 가장 빠른 경로다.

### V3. 수행계획서의 공란은 서류평가 감점 지점이다

p.6은 서류평가에서 확인할 항목을 열거한다 — *"대회 주제와 **이미지·정형데이터 미션**에 대한 이해"*, *"이미지 학습데이터 확보·생성 및 **정형데이터 활용 전략**"*. `docs/04`는 이 두 곳이 모두 `〔팀 작성〕` 플레이스홀더다.

→ **개선**: `docs/04`에 위 ①~⑥을 압축한 정형 미션 문단을 채운다(본 커밋에서 반영).

## 3. 규정·라이선스 취약점

### V6. AI Hub 데이터 승인 리드타임이 일정에 반영되지 않았다

데이터 전략(`docs/03`)의 Real 풀은 AI Hub 4종에 전면 의존한다. AI Hub는 신청·승인 절차를 거치므로 즉시 다운로드가 되지 않는다. 승인이 **9/21 온라인대회 개시** 전에 나지 않으면 데이터 전략 전체가 멈춘다.

→ **개선**: 승인 신청을 **오늘(9/6) 착수**하고, 승인 지연 대비책을 이원화한다.
- 1차 대체: 팀 자체 촬영분 + 공개 라이선스 시설작물 데이터
- 2차 대체: 실제 이미지 확보량이 부족하면 "진짜를 배운다" 가설(자기지도)의 데이터 요구량이 커지므로, **지도학습 브랜치(B0/B1) 비중을 높이는 계획 전환 스위치**를 미리 정의

### V7. AI Hub 파생 가중치와 주최측 이용권의 충돌 — 미검토

p.10은 제출 결과물에 대해 주최·주관기관의 **무상·비독점 이용권**(운영·평가·검증·시상·교육·홍보 및 **비영리 성과확산**)을 규정한다. 한편 AI Hub 데이터는 목적 외 이용·제3자 제공에 제한이 있다.

`docs/01`은 데이터 **원본**의 재제출 갈음 예외(p.5)만 다루고, **그 데이터로 학습한 가중치를 제출하고 주최측이 성과확산에 이용하는 경우**는 다루지 않는다. 학습 가중치는 원본 재배포가 아니므로 대체로 허용 범위로 보이지만, 판단 근거를 팀이 문서로 남겨두지 않으면 최종 검증(p.8)에서 방어할 수 없다.

→ **개선**: (1) 사용하는 AI Hub 각 데이터셋의 이용약관에서 "AI 학습 및 결과물 활용" 조항을 캡처해 근거로 보관, (2) 개막설명회 질문 리스트에 추가(§7), (3) `THIRD_PARTY_NOTICES.md`의 "이용 조건" 칸에 조항 원문을 인용.

### V14. FLUX.1-dev 판단 유보 상태

`docs/01`은 FLUX.1-dev를 "⚠️ 이용조건 명시 필수"로만 두고 사용 여부를 결정하지 않았다. 비상업 라이선스 도구로 만든 학습 데이터 → 그 데이터로 학습한 가중치 → 주최측의 성과확산 이용(p.10)이라는 사슬이 생긴다. 상금이 걸린 대회이므로 "비영리"라는 방어가 완전하지 않다.

→ **개선**: **FLUX.1-dev를 학습 데이터 생성에서 제외**하고, 생성기 계열 다양성은 SD 1.5 / SDXL / SD3 / Kandinsky / GAN 계열로 확보한다. 계열 수는 `docs/03`의 "이점 후 충돌" 원칙상 무한정 늘릴 것이 아니므로, 하나를 빼는 손실이 크지 않다. 라이선스 리스크를 0으로 만드는 쪽이 기대값이 높다.

### 라이선스 표에서 **확인 후 확정**해야 할 항목

## 4. 실행환경·제출물 취약점

### V8. 용량·시간 예산 없이 5브랜치 앙상블을 설계했다

공고문 p.4: *"제출 모델과 코드는 **일반적인 Google Colab 자원 범위**에서 정상적으로 실행 가능하여야 하며, 실행환경의 자원 한계로 정상적인 평가가 어려운 경우 기술적 보완을 요청할 수 있음."*
p.10: 기술적 보완은 **동일 예측결과 재현을 위한 실행환경·경로·설정 수정에 한정**되며, 성능에 영향을 주는 변경은 불가.

즉 **자원 초과로 실패하면 사후에 모델을 줄여서 되살릴 수 없다.** 이건 되돌릴 수 없는 실패 모드다.

현재 설계(B0~B4 + SAM 세그멘테이션 + 원본 해상도 멀티크롭 TTA)의 대략적 부담:

| 항목 | 대략 용량(fp16) | 비고 |
|---|---|---|
| SAM ViT-H | ~1.2 GB | 이미지당 수 초 — **시간이 더 큰 문제** |
| CLIP ViT-L/14 | ~0.9 GB | B1 |
| SPAI | 수백 MB | B2 |
| SD/SDXL VAE (AEROBLADE) | 수백 MB | B4 |
| FerretNet | ~2 MB | B0 |

→ **개선 4가지**
1. **보수적 상한을 지금 가정한다.** 예: 테스트 2,000장 / 총 런타임 90분 → **이미지당 2.7초**. 이 예산을 넘는 브랜치는 기본 구성에서 제외한다. 실제 값은 개막설명회에서 확정하되, 확정 전 설계는 이 가정 위에서 한다.
2. **SAM ViT-H → MobileSAM/FastSAM을 기본값으로.** B3는 정밀 분할이 아니라 "안/밖 영역 정의"만 필요하다. 정밀도 손실 대비 시간·용량 이득이 압도적이다.
3. **백본 공유.** B1의 CLIP 특징을 B3의 의미 스트림이 재사용하면 로딩·연산을 한 번으로 줄인다. 브랜치 수가 아니라 **백본 수**가 비용을 결정한다.
4. **단계적 축소 순서(fp16 → 크롭 수 → 브랜치)를 문서가 아니라 코드의 설정 플래그로** 구현해, 제출 직전 한 줄로 전환 가능하게 한다.

### V9. 결정성 지침이 오히려 실행 실패를 부른다

`docs/01` §6은 `torch.use_deterministic_algorithms(True)`를 요구한다. 그러나 이 플래그는 결정적 커널이 없는 연산(일부 풀링·보간·`index_add` 등)에서 **런타임 예외를 발생시킨다.** 평가환경에서 예외가 나면 그 제출은 실행 실패이고, p.10에 따라 그 불이익은 참가팀이 진다.

→ **개선**: 재현성 요구는 p.8·p.10 모두 **"동일 예측결과의 재현"** 이지 비트 단위 결정성이 아니다.
- 추론 스크립트: `model.eval()`, `torch.no_grad()`, 모든 시드 고정, TTA 크롭 좌표를 **난수가 아닌 결정적 규칙**으로 산출 → 이것만으로 동일 입력·동일 출력이 보장된다
- `use_deterministic_algorithms(True)`는 **개발 중 검증용으로만** 켜고, 제출 스크립트에서는 끈다. 대신 `CUBLAS_WORKSPACE_CONFIG` 없이도 동작하는지 확인
- 검증 절차: 네트워크 차단 상태에서 **동일 입력으로 2회 실행 → 출력 완전 일치** 확인 (기존 체크리스트 유지)

### V15. 예시 이미지 취급이 문서 간에 충돌한다

`docs/02` §6은 예시 이미지를 **정찰(EDA)** 대상으로 쓰라 하고, `docs/03` §4.5는 **검증 전용**이라 한다. 공고문 p.4는 *"소수의 예시 이미지"* 라고 명시하므로, 수가 적어 **검증셋으로서의 통계적 신뢰도는 없다.**

→ **개선**: 역할을 다음으로 통일한다.
- **1순위: 정찰** — 생성기 계열·재인코딩 여부·해상도 분포 추정 → 학습 데이터 구성과 브랜치 가중치 결정
- **2순위: sanity check** — 파이프라인이 명백히 깨졌는지 확인하는 용도. "검증셋"이라 부르지 않는다
- **금지: 학습 투입** (과적합, 그리고 기준점 상실)

## 5. 기술 전략 취약점

### V10. B3는 "우리가 만든 합성 기법"에 과적합된다

`docs/03` §4.1의 LOGO CV는 **생성기 계열** 단위다. 그런데 유형 ①②를 담당하는 B3의 학습 신호는 우리가 선택한 **블렌딩 기법**(알파 / Poisson / 하모나이제이션 / 인페인팅)에서 나온다. 운영측이 다른 합성 도구를 썼다면 LOGO CV는 이 실패를 **탐지하지 못한다** — 축이 다르기 때문이다.

→ **개선: Leave-One-Blending-Out CV를 추가한다.**
```
블렌딩 기법을 J개 그룹으로 분할 (알파 / Poisson / 하모나이제이션 / 인페인팅 / 기타)
for j in 1..J:
    학습: 기법 j를 제외한 전부
    평가: 기법 j
→ 최악 케이스가 B3의 실전 하한선
```
특히 **인페인팅 기반 경계 융합을 제외했을 때의 성능**을 본다. 경계가 가장 깨끗한 방식이고, 운영측이 이 방식을 썼을 가능성이 높기 때문이다.

### V11. 유형 ②는 동일 카메라 합성이면 영역 대조 신호가 소멸한다

유형 ②(현장 작물 + 다른 현장 배경)에서, 두 소스가 **같은 농가·같은 카메라**에서 촬영되었다면 — 그리고 운영측이 자기 데이터로 합성했다면 그럴 개연성이 높다 — B3가 의존하는 신호가 대부분 무력화된다.

| B3 특징 | 동일 카메라일 때 |
|---|---|
| 노이즈 잔차 통계 (SRM/Bayar) | **거의 동일** |
| JPEG 블록 정렬·양자화 흔적 | 동일 파이프라인이면 **동일** |
| 색온도 / 화이트밸런스 | 같은 시설·같은 시간대면 **유사** |
| 초점·블러 척도 | 유사할 수 있음 |

남는 신호는 셋뿐이다: **① 경계의 국소 아티팩트**(하모나이제이션 자국, 인페인팅 잔물결, 알파 페더링), **② 기하·조명 정합**(원근, 그림자 방향·길이, 지평선 대비 스케일), **③ 의미적 정합**(캐노피 밀도와 배지·유인줄 배치의 모순, 작물 생육 단계와 시설 구조의 불일치).

→ **개선**
1. B3의 특징 집합에 **경계 국소 아티팩트 전용 브랜치**를 명시적으로 추가하고, 마스크 경계 밴드(±k 픽셀)에서만 계산하는 통계를 넣는다
2. 자체 생성 데이터에서 **유형 ②의 절반은 반드시 동일 농가·동일 카메라 소스로 합성**해 이 난이도를 학습·검증에 포함시킨다 (현재 `docs/03`은 소스 동일성 조건을 지정하지 않았다)
3. 그래도 실패하면 최후 보루는 §"진짜를 배운다" 브랜치다 — 합성 경계는 자연 이미지의 국소 픽셀 의존성을 어떤 형태로든 위반하기 때문

### V12. 임계값이 테스트셋 비율 변화에 무방비다

`docs/02` §4.2는 *"확률을 출력하고 0.5를 기본값"* 으로 둔다. 그러나 지표가 Accuracy나 F1이면 **테스트셋의 real:fake 비율**이 임계값 최적점을 좌우한다. 그 비율은 미공개이며 우리 로컬 검증셋 비율과 다를 수 있다.

→ **개선**
- 융합 출력은 **캘리브레이션된 확률**로 유지하고, **prior shift 보정**(로그오즈에 `log(π_test/π_train)`을 더하는 형태)을 코드에 미리 넣어 비율 가정을 한 줄로 바꿀 수 있게 한다
- 개막설명회에서 비율·지표를 확인(§7)한 뒤 그 값을 주입한다
- 지표가 AUC로 확정되면 임계값 문제는 사라지므로, **확인 전까지 임계값 튜닝에 시간을 쓰지 않는다**

### V13. FerretNet 가중치 확보에 기한이 없다

`docs/01`은 Baidu Disk 접근 실패 대비책(코드만 사용해 자체 학습)을 적어두었으나 **언제까지 판단할지**가 없다. 자체 학습으로 전환하면 학습 데이터·시간 계획이 달라진다.

→ **개선**: **9/18(개막설명회일)까지 확보 여부를 확정**하고, 실패 시 그날 자체 학습으로 전환한다. 온라인대회 개시(9/21) 후에 판단하면 1주차 베이스라인 제출 일정이 무너진다.

## 6. 저장소·데이터 취급 취약점

### V16. `.gitignore`에 구멍이 있다

현재 규칙은 이미지 확장자와 `data/`·`provided/` 등 디렉토리를 막는다. 그러나 공고문 p.4가 명시한 운영측 제공물은 *"예시 이미지, **샘플 코드 및 관련 파일**"* 이다.

- 운영측 제공 **문서·아카이브** (`.pdf`, `.hwp`, `.xlsx`, `.7z`)

→ **개선**: 본 커밋에서 `.gitignore`를 보강했다. 원칙은 *"운영측에서 받은 것과 개인정보가 담긴 것은 저장소에 두지 않는다"* 이며, 필요한 것은 **경로만 코드에서 참조**한다.

### V17. 대회 데이터를 원격 세션·클라우드에 올리는 것도 "제3자 제공"이다

p.9: *"대회 운영 측이 제공한 데이터는 대회 수행 목적으로만 이용하여야 하며, **제3자에게 제공**하거나 온라인에 공개·배포할 수 없음."*

README는 "외부 AI 서비스·검증 API·클라우드 스토리지 업로드 금지"를 이미 적었으나, **원격 개발 환경(클라우드 IDE, 원격 에이전트 세션, 노트북 호스팅)에 데이터를 올리는 것**은 명시하지 않았다. 이 경로가 실무에서 가장 새기 쉽다.

- Colab 사용은 **제출용 추론 코드의 실행 검증**에 한정하고, 그때도 대회 제공 데이터가 아니라 자체 샘플로 검증한다

→ **현장 적용상 보강안**: 이 모델의 현장 용도를 구체적으로 제시한다. 스마트팜 데이터 수집 파이프라인에서 **업로드 이미지의 신뢰성 게이트**로 동작시키는 시나리오 — 병해충 진단 서비스나 생육 모니터링에 오염·조작 이미지가 유입되는 것을 차단하고, B3의 **위조 히트맵으로 어느 영역이 왜 의심되는지 현장 담당자에게 제시**한다. 경량 브랜치(FerretNet 1.06M)만으로 엣지 실행이 가능하다는 점이 이 논지를 뒷받침한다. p.8·p.9의 *"현장 적용 가능성"* 평가 항목과 직결된다.
